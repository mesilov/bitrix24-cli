# Недельный отчёт по проекту

`task:report` показывает четыре показателя доступных задач выбранного проекта.
По умолчанию отчёт охватывает весь проект за прошлую календарную неделю.
Необязательный исполнитель сужает каждый показатель внутри проекта.

```sh
b24cli task:report --group-id 234 --timezone Asia/Bishkek
b24cli task:report --group-id 234 --responsible 14 --week this-week --timezone Asia/Bishkek --json
b24cli task:report --group-id 234 --week 2026-10-14 --plain
```

| Показатель | Правило |
| --- | --- |
| Закрытые за неделю | Текущий completed и фактическая closedDate в периоде; повторно открытые исключены |
| Ожидают контроля сейчас | Текущий supposedly_completed независимо от даты создания/передачи |
| Новые за неделю | Количество уникальных задач по createdDate независимо от текущего статуса |
| В работе сейчас | Количество уникальных in_progress; pending, deferred и контроль исключены |

Исполнитель означает текущего ответственного. Автор новых задач его не подменяет.
Созданная и завершённая за неделю задача участвует в двух соответствующих показателях.
Повторные закрытия одной задачи не считаются отдельными событиями.

Неделя — [понедельник 00:00, следующий понедельник 00:00) в IANA timezone.
`--week` принимает last-week (по умолчанию), this-week или корректную дату
YYYY-MM-DD внутри выбранной недели. Будущая неделя отклоняется. Для текущей
недели создание/закрытие ограничены временем начала формирования отчёта.
Границы рассчитываются календарно с учётом DST, а не фиксированными 168 часами.
`--timezone` по умолчанию берётся из TZ или PHP; фактический пояс выведен явно.

Контроль и работа — текущие наблюдения, в том числе при отчёте за прошлую неделю.
Показатели не восстанавливают исторический состав проекта, ответственного или
статусы на конец недели. ReportAt/observedUntil показывают интервал сбора;
атомарный снимок не обещается. Отчёт охватывает доступную подключению выборку,
поэтому пустой доступный список не доказывает отсутствие скрытых задач.

Четыре выборки используют заранее выбранный tasks.task.list REST1.
Strict-rest3 отклоняет команду до credentials/API; операции записи не выполняются.
Общий `--max-scan N` (по умолчанию 10000) ограничивает просмотренные строки всех
секций, включая дубликаты. Списки не обрезаются дополнительным скрытым лимитом.
При неполноте точный count неизвестен: JSON возвращает null, observedCount и
причины; подтверждённые строки сохраняются. Human показывает «неизвестно,
найдено N», plain — literal null и отдельные summary-строки. Exit code 3
означает partial. Увеличение бюджета помогает при scan-budget-exhausted;
ошибки прав и противоречивые данные требуют устранения указанной причины.

JSON сохраняет data/meta/error и четыре секции closedTasks,
awaitingControlTasks, newTasks, inProgressTasks. Plain печатает TSV без
заголовка в stdout: section, recordType, id, title, responsibleId, groupId,
status, createdDate, closedDate, count, observedCount, complete, reason.
Две секции списков имеют task-строки; все четыре имеют summary-строки.
Заголовок и контекст периода/области печатаются в stderr.
