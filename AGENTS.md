# Память проекта и правила разработки

Разработка в этом репозитории ведётся по OpenSpec.

При сопровождении репозитория используй локальный скилл [bitrix24-cli-maintainer](.agents/skills/bitrix24-cli-maintainer/SKILL.md).

- Требования, решения и задачи хранятся в `openspec/`: актуальные спецификации — в `openspec/specs/`, изменения — в `openspec/changes/`.
- Для новых функций, исправлений и изменений поведения сначала создавай или обновляй OpenSpec change с необходимыми артефактами, затем выполняй его задачи.
- Каждое поставленное GitHub issue должно трассироваться в OpenSpec change: ссылка на issue в `proposal.md`, идентификатор и путь change в описании issue. После архивирования change обновляй путь в issue.
- Используй локальные скиллы `openspec-*` из `.agents/skills/`: подготовка — `openspec-propose`, реализация — `openspec-apply-change`, проверка — `openspec-verify-change`, завершение — `openspec-archive-change`.
- Отмечай выполненные задачи по факту реализации и проверок. Архивируй изменение после завершения реализации и проверки соответствия спецификациям.
- Планирование и ведение разработки выполняй через OpenSpec. Не используй workflow Superpowers и не создавай его планы в `docs/superpowers/`.
- Сохраняй незакоммиченные изменения пользователя, не относящиеся к текущей задаче.
- До версии 1.0.0 пиши README как документацию первой сборки: описывай текущие команды и конфигурацию без упоминаний обратной совместимости, прежнего поведения и миграции с предварительных сборок.

## Обязательный MCP документации Битрикс24

- Для проекта обязателен [официальный MCP документации Битрикс24](https://apidocs.bitrix24.ru/ai-tools/mcp.html). Подключение Codex хранится в [.codex/config.toml](.codex/config.toml): сервер `bitrix24_dev`, URL `https://mcp-dev.bitrix24.tech/mcp`, `enabled = true`, `required = true`. При ошибке инициализации включённого сервера Codex должен остановить запуск или возобновление сессии.
- При работе с документацией Битрикс24 и проверке REST API-контрактов обязательно обращайся к этому MCP: сначала `bitrix-search`, затем соответствующий `bitrix-*-details` по точному имени из поиска. Сохраняй ссылки на официальные источники и границы проверки в OpenSpec change.
- Проектный config загружается только для доверенного проекта. Перед API-зависимой работой проверь effective config командой `codex mcp get bitrix24_dev --json` из checkout и выполни реальный запрос MCP; наличие сервера в конфигурации само по себе не подтверждает подключение. После изменения конфигурации начни новую сессию или возобнови её с актуальными настройками. В другом AI-клиенте подключи тот же endpoint по Streamable HTTP.
- Если MCP недоступен, восстанови подключение или явно сообщи препятствие и останови зависимую от документации работу; не подменяй проверку API-контрактов памятью модели. Сервер предоставляет только документацию, не выполняет вызовы к порталу и не требует токенов или вебхуков; не передавай ему секреты.
