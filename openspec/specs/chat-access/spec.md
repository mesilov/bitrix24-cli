# chat-access Specification

## Purpose
Предоставляет агенту проверяемый доступ к сообщениям общего чата проекта, чата задачи и произвольного доступного группового чата для получения контекста и общения от имени подключения.

## Requirements

### Requirement: Standalone chats namespace
CLI SHALL предоставлять `chats:resolve`, `chats:find`, `chats:messages:list`, `chats:send` и `chats:add` как самостоятельный namespace. Работа с обычным групповым чатом SHALL не требовать TASK_ID/GROUP_ID. Существующий `task:chat:*` SHALL сохраняться; общий namespace `chat:*` не вводится.

#### Scenario: Чат без проекта и задачи
- **WHEN** пользователь передаёт URL обычного группового чата либо chat123 в chats:messages:list или chats:send
- **THEN** CLI работает с этим доступным чатом без поиска обязательной задачи или проекта
- **AND** новые команды зарегистрированы под chats:*, а task:chat:* сохраняет собственный вход через TASK_ID

### Requirement: CHAT-01 — Получить контекст за период
CLI SHALL предоставлять сообщения выбранного чата за заданный календарный период с авторами, временем, ID и полнотой. Вызывающий агент составляет саммари; CLI не требует встроенного LLM.

#### Scenario: Вчерашняя переписка проекта
- **WHEN** пользователь просит посмотреть общий чат проекта за прошлый день и дать саммари
- **THEN** агент получает сообщения за вчерашний календарный день в выбранной IANA timezone
- **AND** данные позволяют сослаться на ID сообщений с решениями, договорённостями и открытыми вопросами
- **AND** неполный источник явно отмечается до составления саммари

### Requirement: CHAT-02 — Сообщить команде
CLI SHALL позволять отправить текст в однозначно выбранный доступный чат по URL, типизированному ID или точному названию. Успех SHALL подтверждать адресата и созданное сообщение; неоднозначный выбор не выполняет запись.

#### Scenario: Уведомление об отсутствии
- **WHEN** пользователь просит написать в чат с указанным названием, что он сегодня отсутствует
- **THEN** агент однозначно выбирает доступный чат и отправляет заданный текст
- **AND** возвращает подтверждённый адресат и ID сообщения либо явный неопределённый исход

### Requirement: Typed destination resolution
CLI SHALL различать общий чат проекта, чат задачи, произвольный групповой чат и ссылку на сообщение. URL SHALL разбираться локально с проверкой портала выбранного подключения. taskId, groupId, chatId и messageId SHALL не подменять друг друга.

#### Scenario: Общий чат проекта
- **WHEN** передан URL с IM_DIALOG=sg234 либо адресат group:234
- **THEN** выбирается общий чат проекта 234, а не chat234 и не совокупность чатов задач

#### Scenario: Задача и её чат
- **WHEN** передан task:123 либо поддерживаемая ссылка на задачу 123
- **THEN** CLI подтверждает связь задачи 123 с её чатом перед работой с ним
- **AND** отсутствие подтверждённой связи блокирует операцию

#### Scenario: Ссылка на сообщение
- **WHEN** поддерживаемая ссылка содержит явный адресат чата и отдельный ID сообщения
- **THEN** для чтения периода используется адресат чата, а ID сообщения не становится chatId или фильтром периода

#### Scenario: Недопустимая ссылка
- **WHEN** URL указывает другой портал, неподдерживаемую форму или конфликтующие адресаты
- **THEN** CLI отклоняет ввод без перехода по ссылке и без запросов к чужому хосту
- **AND** bare numeric ID не принимается как неоднозначный тип адресата

### Requirement: Complete title search before sending
CLI SHALL искать по названию обычные групповые чаты, проекты и задачи с конечным бюджетом и показывать ID, название и контекст каждого кандидата. Выбор по названию для записи SHALL требовать ровно одного точного совпадения названия в полной доступной выдаче; совпадение по участнику недостаточно.

#### Scenario: Несколько точных названий
- **WHEN** два доступных чата имеют указанное название
- **THEN** CLI возвращает кандидатов и требует явный адресат
- **AND** сообщение не отправляется

#### Scenario: Неполная либо нерелевантная выдача
- **WHEN** бюджет поиска исчерпан, страница недоступна либо результат совпал только по имени участника
- **THEN** CLI не объявляет единственный просмотренный чат однозначным адресатом для отправки
- **AND** ноль подтверждённых результатов не превращает ошибку доступа в «чат не найден»

#### Scenario: Поиск по проектам и задачам
- **WHEN** указанное название совпадает с названием проекта или заголовком задачи
- **THEN** chats:find возвращает кандидата sgN или task:N с контекстом проекта или задачи, даже если IM-поиск чатов его не находит
- **AND** для задачи сравнивается заголовок задачи, а не название её чата

#### Scenario: Кандидат без подтверждённого чата
- **WHEN** проект или задача найдены, но их чат недоступен или связь не подтверждена
- **THEN** кандидат показывается с причиной и не может стать адресатом записи

### Requirement: Calendar period and bounded history
CLI SHALL принимать точный интервал [from,to) либо yesterday с IANA timezone и одним now на запуск. Чтение SHALL использовать конечный бюджет, дедупликацию и устойчивый порядок. Полнота SHALL означать проверенную доступную историю выбранного периода.

#### Scenario: Границы вчерашнего дня
- **WHEN** выбран yesterday в timezone с переходом DST либо на границе месяца/года
- **THEN** from — местная полночь вчера, to — местная полночь сегодня
- **AND** сообщение в from включено, сообщение в to исключено; сутки не заменяются фиксированными 24 часами

#### Scenario: Несколько страниц и пустой день
- **WHEN** за период доступно более 50 сообщений либо сообщений нет
- **THEN** CLI обходит необходимые страницы и возвращает каждое подходящее сообщение один раз в порядке времени и ID
- **AND** пустой полный результат выдаётся только после подтверждения границ доступной истории

#### Scenario: Непрочитанные сообщения в чате
- **WHEN** в выбранном чате есть непрочитанные сообщения
- **THEN** обход истории начинается с последнего сообщения чата, а не с окна первого непрочитанного
- **AND** чтение не меняет счётчик и позицию непрочитанного

#### Scenario: Нельзя доказать полноту
- **WHEN** исчерпан бюджет, достигнут лимит вывода, нарушена пагинация или недоступна следующая страница
- **THEN** доступные сообщения сохраняются, complete=false, причина и exit 3 сообщаются агенту
- **AND** отсутствие доказанного порядка дат по ID не позволяет преждевременно остановить обход только по старому timestamp

### Requirement: Explicit send outcome
CLI SHALL поддерживать текст, файл или stdin и dry-run с адресатом и текстом. Успешная отправка SHALL возвращать ID сообщения. Потеря ответа SHALL сохраняться как outcomeUnknown без автоматического повтора записи.

#### Scenario: Dry-run
- **WHEN** отправка вызвана с dry-run
- **THEN** CLI показывает выбранный адресат, текст и проверочные чтения без создания сообщения

#### Scenario: Потеря ответа сервера
- **WHEN** запрос мог создать сообщение, но результат не получен
- **THEN** CLI сообщает outcomeUnknown, а не confirmed success
- **AND** повторная отправка автоматически не выполняется

### Requirement: Policy access and machine output
CLI SHALL сохранять human/plain/JSON контракт, объявлять полные маршруты и scope im до исполнения. strict-rest3 SHALL отклонять REST1 план до подключения. Чтение SHALL не менять read state, не присоединять пользователя и не повышать права.

#### Scenario: Доступ запрещён
- **WHEN** нет scope im либо доступа к выбранному чату
- **THEN** CLI возвращает явный отказ, не пустую успешную историю
- **AND** существующие незатронутые task-команды сохраняют своё поведение

#### Scenario: Проверяемый источник для агента
- **WHEN** история возвращается в JSON
- **THEN** вывод содержит адресат, период/timezone, сообщения с ID/автором/временем, число просмотренных сообщений и complete/reason
- **AND** human/plain сохраняют смысл ошибок и полноты

### Requirement: CHAT-06 — Завести чат для рассылки команде
CLI SHALL позволять создать от имени пользователя подключения закрытый или открытый групповой чат с заданным названием, описанием и участниками. Успех SHALL возвращать адресат `chatN`, пригодный для `chats:send`. Создание каналов Битрикс24 SHALL не заявляться: REST создаёт только типы `CHAT` и `OPEN`.

#### Scenario: Чат новостей для своей группы
- **WHEN** пользователь просит завести чат «ИИ-новости» вместе со своей группой, чтобы агент писал туда новости
- **THEN** агент получает ID участников, создаёт один чат с этим названием и участниками
- **AND** получает подтверждённый адресат chatN и отправляет в него сообщение через chats:send

#### Scenario: Просьба создать канал
- **WHEN** пользователь просит именно канал
- **THEN** документация и справка команды указывают, что REST создаёт только закрытый или открытый групповой чат
- **AND** CLI не принимает тип, отличный от CHAT и OPEN

### Requirement: Duplicate title guard before creation
CLI SHALL до создания искать доступные пользователю групповые чаты с точно таким же названием в полной выдаче поиска с конечным бюджетом. Совпадение либо неполный поиск SHALL блокировать запись без явного разрешения дубля.

#### Scenario: Повторный запуск агента
- **WHEN** доступный групповой чат с точно таким же названием уже существует
- **THEN** CLI не создаёт чат и возвращает код chat-exists с адресатами существующих чатов
- **AND** создание выполняется только при явном флаге разрешения дубля

#### Scenario: Поиск не доказал отсутствие дубля
- **WHEN** бюджет поиска исчерпан, пагинация не продвигается либо страница поиска недоступна
- **THEN** CLI не создаёт чат и возвращает search-incomplete с состоянием поиска
- **AND** совпадение только по имени участника не считается дублем

### Requirement: Explicit creation outcome
CLI SHALL показывать в dry-run название, тип, описание, участников и проверочные чтения без записи. Создание SHALL выполняться одним вызовом без повтора; потеря ответа SHALL сообщаться как outcomeUnknown. После создания CLI SHALL сверять название и запрошенных участников созданного чата.

#### Scenario: Dry-run
- **WHEN** создание вызвано с dry-run
- **THEN** CLI выполняет только проверку дубля и показывает план создания и проверочных чтений
- **AND** чат не создаётся

#### Scenario: Потеря ответа сервера
- **WHEN** запрос мог создать чат, но ID чата не получен
- **THEN** CLI сообщает outcomeUnknown и подсказывает проверить chats:find по названию
- **AND** повторное создание автоматически не выполняется

#### Scenario: Участник не добавлен
- **WHEN** чат создан, но среди его участников нет кого-то из запрошенных либо название не совпало
- **THEN** CLI возвращает ID созданного чата, список недостающих участников и exit 3
- **AND** результат не объявляется полностью подтверждённым

#### Scenario: Политика и права
- **WHEN** выбрана политика strict-rest3 либо у подключения нет scope im
- **THEN** команда отклоняется до записи с явной причиной
- **AND** некорректный ID участника, пустое название или неподдерживаемый тип отклоняются как ошибка использования до запросов к API
