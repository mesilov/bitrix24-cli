# Proposal

## Why

Новый пользователь после установки запускает `b24cli auth:login work`, и CLI просит `HTTPS incoming webhook:`. Ни README, ни `docs/auth.md`, ни `b24cli auth:login --help` не объясняют, что это за URL, где его создать в Битрикс24 и почему ввод скрыт. Есть только фраза «Подготовьте входящий вебхук портала с правами для нужных команд». В [#152](https://github.com/mesilov/bitrix24-cli/issues/152) пользователь не смог подключить портал по документации и нашёл ответ только через ИИ-агента.

## What Changes

- В `docs/auth.md` появляется раздел «Где взять входящий вебхук» со стабильным якорем `#incoming-webhook`. В нём:
  - шаги создания по официальной документации: *Разработчикам → Готовые сценарии → Другое → Входящий вебхук*, выбор прав в блоке *Настройка прав*, копирование поля *Вебхук для вызова rest api*, кнопка *Создать*;
  - что делать, если пункта *Входящий вебхук* нет (право создавать вебхуки выдаёт администратор) или если REST API недоступен на тарифе;
  - вид URL с вымышленным примером `https://your-company.bitrix24.ru/rest/1/<секретный код>/` и разбор его частей;
  - почему ввод скрыт: код в пути URL даёт доступ к порталу с правами создателя вебхука;
  - где позже найти и перевыпустить вебхук (список *Интеграции*, *Перегенерировать*) и как затем выполнить `auth:login NAME --replace`;
  - ссылки на официальные статьи.
- Какие права отметить, этот раздел не перечисляет. Он ссылается на таблицу прав в README и матрицу разрешений в `docs/auth-scopes.md`, которые добавляет change `document-webhook-scope-matrix` по [#178](https://github.com/mesilov/bitrix24-cli/issues/178).
- В README в разделе «Подключения и конфигурация» фраза «Подготовьте входящий webhook…» получает ссылку на `docs/auth.md#incoming-webhook`. Блоки команд не меняются.
- Справка `b24cli auth:login --help` начинается с абзаца: что ожидается URL входящего вебхука Битрикс24, путь в интерфейсе, почему ввод скрыт, ссылка на `#incoming-webhook`. Справка по-прежнему не требует credentials и не обращается к порталу.
- Интерактивный `auth:login` в TTY перед скрытым вводом пишет в stderr трёхстрочную подсказку: что вставить, где взять, что ввод не отображается. Строка запроса становится русской: `URL входящего вебхука: `. `--webhook-stdin`, `-n`, `--replace` без TTY и stdout не меняются.
- `CHANGELOG.md` получает запись со ссылкой на #152.

Вне объёма:
- таблица и матрица прав вебхука (#178);
- мастер первого запуска и ASCII-заставка;
- изменение проверки вебхука в `auth:login` и текстов её ошибок.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `connection-configuration`, три новых требования:
  - «Documented incoming webhook setup» — создание вебхука, вид URL и его секретность в `docs/auth.md`, ссылка из README;
  - «Webhook guidance in auth:login help» — подсказка в справке;
  - «Interactive webhook prompt explains expected input» — подсказка перед скрытым вводом и русская строка запроса.

  Поведение ввода секрета, проверки при входе и хранения credentials не меняется.

## Impact

- Код:
  - `AuthCommandRunner::secret()` — подсказка в stderr и строка вопроса только в интерактивном пути;
  - `LoginCommand::configure()` — текст справки.
- Тесты:
  - `tests/Unit/ConnectionProfilesTest.php` — проверка строки запроса: сейчас ищет `HTTPS incoming webhook:`;
  - тесты справки `auth:login`;
  - `RussianHelpTest`.
- Документация: `docs/auth.md`, README, `CHANGELOG.md`.
- Зависимость от #178: ссылки на `docs/auth-scopes.md#матрица-разрешений` и раздел README «Права вебхука» появятся после merge [PR #232](https://github.com/mesilov/bitrix24-cli/pull/232). Этот change вливается после него, либо до него с ссылкой на `docs/auth-scopes.md` без якоря.
- API: без изменений.

## GitHub issues

- [#152](https://github.com/mesilov/bitrix24-cli/issues/152) — «Сложная установка и запуск». Change покрывает три пункта issue: где взять URL вебхука, почему ввод скрыт, почему справка команды входа не помогает. Также выполняет предложение из комментария дать ссылку на официальную документацию Битрикс24. Список нужных прав закрывает #178. Что пользователь самостоятельно проходит вход по новой документации, проверяется при приёмке.
