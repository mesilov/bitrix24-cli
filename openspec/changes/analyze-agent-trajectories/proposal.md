# Proposal

## Why

Агенты, работающие через bitrix24-cli-skill, пытаются восполнять недостающие возможности b24cli собственной Bash/Python-обвязкой. Первый этап должен фиксировать такие случаи в безопасных локальных карточках и давать пользователю один периодический пакетный разбор вместо ручного пересказа чатов.

## What Changes

- Добавить публичную команду `doctor:problem-trajectory` для регистрации обезличенного сценария и описания необходимого алгоритма обвязки. Триггер — подтверждённая нехватка публичной поверхности CLI; несколько штатных CLI-вызовов сами по себе не проблема.
- Хранить защищённые JSON-карточки в `.problem-trajectories/` рядом с пользовательским `config.json`, используя `--config-dir`, `B24CLI_CONFIG_DIR` и существующие OS defaults.
- Добавить корневой `telemetry`: `collectProblemTrajectories=true`, `maxProblemTrajectoryFiles=100`, `lastProblemTrajectoryProcessingAt=null`, `lastProblemTrajectoryAnalysisOfferedAt=null`. Сбор означает локальное сохранение, без фоновой отправки.
- Предоставить через публичную CLI-поверхность статус/чтение карточек, настройку telemetry и фиксацию предложения/результата обработки. Скилл не читает и не редактирует служебные файлы самостоятельно.
- При запуске скилла проверять накопление и интервал семь суток; предлагать один пакетный разбор, группировать повторения и готовить безопасные кандидаты. Немедленное issue после сохранения можно предложить, но не требовать.
- Передавать только согласованный пакет через публичную CLI-интеграцию с feedback endpoint #15/#32, сохраняя receipt, состояния и идемпотентность.
- Сбор полных историй чатов, Codex JSONL/app-server/rollout adapters, автономный scheduler и автоматические исправления оставить следующему этапу.

## Capabilities

### New Capabilities

- `agent-trajectory-feedback`: локальная регистрация проблемных карточек, публичное управление их состояниями, пакетный разбор из скилла и согласованная передача в feedback.

### Modified Capabilities

- `connection-configuration`: optional корневой telemetry, его effective defaults/валидация, сохранение вместе с профилями и согласованность опубликованной схемы с runtime.

## Impact

План затрагивает `src/Console/`, `src/Infrastructure/Connection/`, `docs/configuration.md`, `docs/config.schema.json`, конфигурационные fixtures и offline tests. Скилл меняется в https://github.com/mesilov/bitrix24-cli-skill после появления публичного контракта CLI. REST API-поля и portal operations не изменяются.

CLI владеет командой, локальными файлами, конфигурацией и транспортом отправки; скилл — обнаружением gap, обезличенным описанием и анализом. Endpoint/публичная публикация используют #15/#32 без изменения их consent/moderation требований. Локальная часть работает без готового сервиса. По карточкам считаются повторения проблем, но не доля проблем среди всех запусков или число пользователей.
