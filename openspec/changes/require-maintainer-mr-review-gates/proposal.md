# Proposal

## Why

Локально согласованы ожидание пяти минут после открытия MR, проверка всех замечаний и запрет merge до их снятия. Эти правила ещё не опубликованы в dev; существующее правило changelog сформулировано только для MR в dev по issue.

## What Changes

- Сделать содержательную запись CHANGELOG.md со ссылкой на issue обязательной для каждого MR; проверять её в собственном diff относительно актуальной целевой ветки перед открытием и merge.
- После открытия MR выжидать минимум пять минут, затем читать reviews, inline threads и комментарии, включая автоматических ревьюеров. Уже открытый более пяти минут MR проверять сразу.
- Устранять замечания до закрытия threads, повторять затронутые проверки и получать актуальное состояние непосредственно перед merge. Все обязательные GitHub CI checks должны завершиться SUCCESS именно на текущем head SHA. Неснятые замечания, открытые threads, активные CHANGES_REQUESTED, отсутствие changelog или незавершённый/неуспешный CI запрещают merge.
- Внести дополнения поверх актуального скилла dev, сохранив JTBD, MCP, синхронизацию ветки, работу с builds и завершение после merge.

## Capabilities

### New Capabilities

Нет. Изменяются инструкции сопровождения, а не поведение CLI.

### Modified Capabilities

Нет. Проверена существующая ci-quality-checks: новый автоматический CI gate не добавляется. Для документационной правки задано skip_specs: true.

## Impact

Изменяются `.agents/skills/bitrix24-cli-maintainer/SKILL.md`, CHANGELOG.md и артефакты этого change. Пользовательские незакоммиченные изменения основного checkout сохраняются. Объём текущей задачи — публикация и проверка отдельного MR в dev. После фактического merge применяются существующие правила архивирования и завершения работы.
