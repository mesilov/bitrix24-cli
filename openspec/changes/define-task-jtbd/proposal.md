# Proposal

## Why

Исследование #10 описало REST/CLI-поверхность, но не зафиксировало принятые пользовательские сценарии. Пользователь согласовал JTBD руководителя проекта, аккаунт менеджера и сотрудника и запросил переписку в чате задачи для всех участников.

## What Changes

- Зафиксировать 16 согласованных JTBD и 3 дополнительных сценария переписки со стабильными ID, ситуацией, желаемым результатом и признаком успеха.
- Создать актуальную спецификацию task-workflows: продуктовые требования к будущему блоку задач; чтение истории и отправка сообщений предусмотрены для каждой роли в пределах прав участника.
- Отделить внутреннюю приёмку результата от принятия клиентом; не назначать ролям произвольные REST permissions.
- Сохранить проверенный каталог tools официального templates-mcp и отметить gap по современному task chat.
- Собрать потенциальный CLI для новой карточки: 43 кандидата и 16 расширений с прежним API; исключить legacy-комментарии, отделить REST3 task routes от IM companions и условных lifecycle mappings.
- Проверить все 19 JTBD по cli-candidates.md/json и jtbd-coverage.md/json. Не выдавать наличие имён за полное покрытие; сохранить ограничения данных, strict-rest3 и оставшиеся решения.
- Применить [Command Line Interface Guidelines](https://github.com/cli-guidelines/cli-guidelines), проверенные на commit `697d6a29fc8c93d3981a755c0c7683507ad39c3e`: создать контракт cli-experience и обновить 59 кандидатов на прямой вызов `b24cli task:<action>` с singular namespace и созданием `task:add`, удобные флаги полей, справку, файловый ввод, JSON/обычный вывод, ошибки и предсказуемую автоматизацию.
- Уточнить границу MVP по решению пользователя: вынести 21 команду зависимостей, рабочих представлений, контекста/препятствий, изменений/клиентских договорённостей и результатов задач в развитие после MVP. Из оставшихся 38 команд 28 остаются кандидатами MVP, 10 требуют решения о прежнем API; наличие в остатке не отменяет API/lifecycle gates. Сохранить все 19 продуктовых JTBD и отдельно показать сокращение MVP command mapping.

- Включить task:time:add/list/update/delete в MVP по решению пользователя, явно допустив документированные REST 1.0 task.elapseditem.* маршруты. Сохранить strict-rest3 restriction и проверки прав/принадлежности записи задаче; дополнить EMP-06 удалением записи.

- Разделить две операции корневых чек-листов и шесть операций пунктов с namespace task:checklist:item:*, добавить item:update и task:find --title TEXT в MVP. Поиск использует REST3 list и локальное совпадение title; legacy checklist admission остаётся отдельным решением.

## Capabilities

### New Capabilities

- `task-workflows`: пользовательские сценарии блока задач: координация проекта, клиентские договорённости, исполнение и переписка участников.
- `cli-experience`: согласованные правила пользовательского интерфейса будущего CLI по CLI Guidelines; структура команд, входы, вывод и проверяемые условия автоматизации.
- `task-mvp-scope`: явная граница MVP, 21 исключённая команда, отдельный допуск legacy/lifecycle и честное отображение покрытия продуктовых JTBD.

### Modified Capabilities

Нет.

## Impact

Изменяются только OpenSpec-артефакты и новая актуальная спецификация. Это фиксация согласованных продуктовых требований, не реализация команд. PHP/API/dependencies не меняются. Требования не являются доказательством runtime-покрытия. Реализация остаётся отдельной работой после проектирования.
