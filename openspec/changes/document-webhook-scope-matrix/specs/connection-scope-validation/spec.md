## ADDED Requirements

### Requirement: Published scope matrix matches the manifest
Документация SHALL содержать матрицу разрешений вебхука, построенную из манифеста требований и каталога маршрутов установленного CLI: для каждой команды, обращающейся к порталу, — обязательные группы scope с альтернативами, scope, нужные только при опциях, необязательные источники и REST-маршруты с версией API. Расхождение матрицы и манифеста MUST обнаруживаться тестами репозитория. Документация MUST NOT обещать, что scope даёт права на конкретную задачу, чат или файл.

#### Scenario: Every portal command has a row
- **WHEN** каталог маршрутов содержит команду, обращающуюся к порталу
- **THEN** матрица содержит строку этой команды с обязательными группами scope и REST-маршрутами, которые совпадают с результатом манифеста для её маршрутов

#### Scenario: Manifest changes without documentation update
- **WHEN** в манифесте или каталоге маршрутов меняется требование команды, а матрица в документации не обновлена
- **THEN** проверка в тестах репозитория завершается ошибкой и называет способ обновления матрицы

#### Scenario: Option-dependent scope is marked
- **WHEN** scope нужен команде только при определённой опции, например `im` для `task:list --unread` или `disk` для локального файла в `task:file:attach`
- **THEN** матрица помечает это условие у команды, а не показывает scope как обязательный для любого вызова
- **AND** каждая такая пометка относится к паре команда/scope, которая есть в манифесте

#### Scenario: Optional source is not a requirement
- **WHEN** маршрут объявлен необязательным источником, например `call.followup.get` со scope `call`
- **THEN** матрица показывает его отдельно от обязательных scope и объясняет, что без него команда работает, но часть данных помечается недоступной

#### Scenario: README answers the minimal setup question
- **WHEN** пользователь читает раздел README о подключении
- **THEN** он видит коды scope с названиями в интерфейсе вебхука, рекомендуемый набор для всех сценариев и ссылку на полную матрицу

#### Scenario: Local commands need no scope
- **WHEN** публичная команда не обращается к порталу, например `auth:list` или `config:*`
- **THEN** матрица перечисляет её среди команд, которым scope не нужны

### Requirement: Access denial troubleshooting guide
Документация проверки разрешений SHALL содержать раздел о действиях при отказе в доступе: где на портале меняются права входящего вебхука, как по видимым признакам отличить нехватку scope от отказа в правах на объект, от политики strict-rest3 и от информационной строки CLI, и как выполнить самодиагностику через `auth:status`.

#### Scenario: Preflight scope check blocks a command
- **WHEN** команда вернула `scope-missing` с exit 4 до обращения к порталу
- **THEN** документация направляет добавить перечисленные scope в блоке «Настройка прав» вебхука и повторить `auth:status`, который показывает владельца, выданные и недостающие scope и затронутые команды

#### Scenario: Strict API policy denial
- **WHEN** команда вернула `policy-denied` при `--api-policy strict-rest3`
- **THEN** документация объясняет, что отказ вызван политикой CLI, а не правами вебхука

#### Scenario: Missing scope after webhook change
- **WHEN** команда вернула `permission-denied` с `apiErrorCode=insufficient_scope`
- **THEN** документация направляет добавить scope в настройках вебхука и выполнить `auth:status` с тем же выбором подключения

#### Scenario: Object access denied despite scopes
- **WHEN** команда вернула `permission-denied` без `insufficient_scope`, а `auth:status` не показывает недостающих scope
- **THEN** документация объясняет, что запросы выполняются с правами пользователя, создавшего вебхук, и что нужно проверить его доступ к задаче, чату или файлу, а не галочки scope

#### Scenario: REST 1.0 route notice
- **WHEN** пользователь видит в stderr строку `This operation used an explicitly admitted REST 1.0 route.`
- **THEN** документация объясняет, что это сведения о политике маршрутов CLI по умолчанию, а не white-list портала, и что настраивать на портале ничего не нужно
