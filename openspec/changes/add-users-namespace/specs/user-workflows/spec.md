# User Workflows Spec Delta

## Purpose

Фиксировать рабочие сценарии поиска сотрудников и выбора адресатов в компании для руководителя проекта, аккаунт менеджера и сотрудника, с проверяемыми ID и явным происхождением информации.

## ADDED Requirements

### Requirement: USR-01 — Определить себя в выбранном портале
CLI SHALL позволять участнику узнать, от имени какого пользователя выполняется выбранное подключение, чтобы правильно понимать «на меня» и использовать свой проверяемый ID в следующих командах. Роль JTBD SHALL не предоставлять дополнительных прав на портале.

#### Scenario: Identify the acting employee
- **WHEN** сотрудник готовит выборку своих задач или передаёт свой ID коллеге
- **THEN** users:current показывает пользователя текущего подключения и его ID
- **AND** признак успеха: ID получен с выбранного портала, а не из defaults или догадки по URL

### Requirement: USR-02 — Найти коллег своего отдела
CLI SHALL позволять сотруднику получить активных коллег по текущему отделу оргструктуры, чтобы выбрать сотрудника для обсуждения, помощи или распределения работы. Участники проекта или группы задач SHALL не подменять коллег по отделу.

#### Scenario: Choose a colleague for help
- **WHEN** сотрудник хочет запросить помощь у коллег своего отдела
- **THEN** users:colleagues предоставляет список с ID и доступными ФИО/email в выбранном отделе
- **AND** признак успеха: список исключает самого сотрудника, его источник и полнота понятны; при нескольких отделах выбор задан явно

### Requirement: USR-03 — Найти непосредственного руководителя
CLI SHALL позволять сотруднику определить непосредственного руководителя по выбранной ветке оргструктуры, чтобы передать вопрос или препятствие правильному адресату. Настроенный рабочий руководитель SHALL быть доступен отдельно с явным источником и может отличаться от руководителя по оргструктуре.

#### Scenario: Escalate an obstacle
- **WHEN** сотруднику требуется решение непосредственного руководителя
- **THEN** users:manager показывает ID руководителя по оргструктуре либо честно сообщает его отсутствие/недоступность
- **AND** признак успеха: происхождение ID и отдел понятны, настроенный другой managerId не подменяет оргструктуру

#### Scenario: Use a separately configured working manager
- **WHEN** рабочие договорённости требуют обращаться к другому руководителю
- **THEN** users:manager --source config показывает сохранённого руководителя с source=config
- **AND** признак успеха: рабочий выбор не изменяет оргструктуру и не выдается за её данные

### Requirement: USR-04 — Сохранить рабочих адресатов профиля
CLI SHALL позволять участнику сохранить ID дефолтного наблюдателя и рабочего руководителя отдельно для каждого портала, чтобы использовать согласованных адресатов в дальнейших сценариях. Сохранение настроек SHALL не менять портал. Опциональная автодобавка наблюдателя SHALL применяться при создании задачи только при включённом профильном флаге.

#### Scenario: Keep portal-specific roles
- **WHEN** участник настраивает work с observerId=5 и managerId=9, а clientA имеет другие рабочие роли
- **THEN** connection:show с выбранным профилем показывает его default.users без смешивания адресатов разных компаний
- **AND** признак успеха: оба ID можно проверить, отсутствие настроек не вызывает автоматический выбор человека

#### Scenario: Opt in to the default observer
- **WHEN** профиль имеет observerId=5 и autoAddObserver=true, а участник создаёт задачу
- **THEN** после создания CLI назначает ID 5 наблюдателем и показывает результат обоих шагов
- **AND** при false/отсутствующем флаге задача создаётся без автоматического назначения наблюдателя; признак успеха: настройка не вызывает неожиданных дополнительных записей

### Requirement: USR-05 — Найти произвольного сотрудника компании
CLI SHALL позволять участнику найти активного сотрудника по ФИО либо точному email, чтобы получить проверяемый ID для назначения или коммуникации. Неоднозначное совпадение SHALL оставаться списком кандидатов; CLI SHALL не назначать человека по одному только тексту поиска.

#### Scenario: Find an employee before assigning a task
- **WHEN** руководитель проекта знает ФИО либо email сотрудника, но не его ID
- **THEN** users:find возвращает найденных кандидатов и данные для их различения
- **AND** признак успеха: участник выбирает явный ID для следующей команды, а пустая/неполная выборка не превращается в вымышленное назначение
