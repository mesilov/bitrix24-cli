# Design

## Context

См. мотивацию в `proposal.md`. В проверенном `origin/dev` каталог прикладных и локальных команд хранится в `src/Bootstrap/CommandCatalog.php`; стандартные list/help/completion добавляет Symfony Console. Тексты справки задаются в `src/Console/Command/**`, а глобальные опции — в bootstrap/runtime. В README есть раздел CLI-команд; `docs/development.md` ссылается на архивный command-map исходных 30 команд и отдельную проверку результатов задач. В `openspec/changes/define-task-jtbd/jtbd-coverage.md` остаётся развиваемая карта JTBD. Это наблюдения по исходникам, а не доказательство корректности справки релиза 0.2.0.

## Goals / Non-Goals

**Goals:** Получить воспроизводимую сверку справки и документации для одного version/source SHA и полный перечень проверенных команд; дать скиллу устойчивые публичные примеры.

**Non-Goals:** Новые команды, API-маршруты, смена флагов, автоматическая публикация 0.2.0 и выполнение изменяющих команд на рабочем портале.

## Decisions

1. Источник списка — фактический `b24cli list` проверяемой версии с дополнительной сверкой `CommandCatalog::all()`. Фиксированное число команд 0.1.0 или список из планов непригодны: dev продолжает меняться до релиза.
2. Для каждой публичной команды проверить `COMMAND --help` и `help COMMAND` без credentials и API-запросов. Аргументы, опции и defaults сверяются с определением команды; наличие правдоподобного текста недостаточно для доказательства синтаксиса примеров. Проверка примеров использует parser/fixture transport; реальные записи на портале не нужны.
3. В `docs/cli-command-map.md` разместить текущую карту всех публичных команд: назначение, пример, ссылка на справку/документацию и релевантное интеграционное покрытие либо явное указание его отсутствия. README содержит обзор и ссылку на карту. Архивные command-map остаются историческими свидетельствами; ссылки JTBD согласуются с актуальной картой. Это устраняет разрозненность текущих ссылок без переписывания истории.
4. Материалы скилла обновляются через отдельное issue #6; README приложения ссылается на `https://github.com/mesilov/bitrix24-cli-skill`. Скилл опирается только на публичный CLI и сохраняет существующие ограничения.
5. Delta specs пропущены (`skip_specs: true`): аудит обеспечивает выполнение уже существующего help-контракта. Обнаруженная потребность в изменении поведения требует отдельного OpenSpec change.

## Risks / Trade-offs

- [dev меняется до релиза] → зафиксировать source SHA исходной сверки и повторить проверку на артефакте 0.2.0 перед закрытием issue.
- [Пример успешно разобран, но права/данные портала отличаются] → различать синтаксическую проверку и live acceptance; не заявлять последнее по справке.
- [Карта скилла расходится с приложением] → взаимные ссылки issues и одинаковая версия/source SHA сверки.

## Migration Plan

Изменения справки и документации доставляются обычным MR в dev. Обратный ход — revert соответствующего documentation/help commit; данные пользователя и подключения не мигрируют. По завершении проверки архивировать change и обновить путь в обоих issues.
