# Design

## Context

См. мотивацию в `proposal.md`. В проверенном `origin/dev` каталог прикладных и локальных команд хранится в `src/Bootstrap/CommandCatalog.php`; стандартные list/help/completion добавляет Symfony Console. Тексты справки задаются в `src/Console/Command/**`, а глобальные опции — в bootstrap/runtime. Проверенный корневой `b24cli --help` сейчас показывает `Description: List commands` и `Usage: list [options]`, включая шаблонный пример namespace test; командная справка `task:add --help` уже содержит назначение и примеры. В README есть раздел CLI-команд; `docs/development.md` ссылается на архивный command-map исходных 30 команд и отдельную проверку результатов задач. В `openspec/changes/define-task-jtbd/jtbd-coverage.md` остаётся развиваемая карта JTBD. Это наблюдения по dev, а не доказательство корректности справки релиза 0.2.0.

## Goals / Non-Goals

**Goals:** Сделать корневой help обзором приложения с назначением, списком команд и примерами задач; добавить информационный вывод `--about` с назначением, версией, автором, лицензией и ссылками; получить воспроизводимую сверку справки и документации для одного version/source SHA и полный перечень проверенных команд; дать скиллу устойчивые публичные примеры.

**Non-Goals:** Новые прикладные команды, API-маршруты, переименование существующих флагов, автоматическая публикация 0.2.0 и выполнение изменяющих команд на рабочем портале.

## Decisions

1. Источник списка — фактический `b24cli list` проверяемой версии с дополнительной сверкой `CommandCatalog::all()`. Фиксированное число команд 0.1.0 или список из планов непригодны: dev продолжает меняться до релиза.
2. Для каждой публичной команды проверить `COMMAND --help` и `help COMMAND` без credentials и API-запросов. Аргументы, опции и defaults сверяются с определением команды; наличие правдоподобного текста недостаточно для доказательства синтаксиса примеров. Проверка примеров использует parser/fixture transport; реальные записи на портале не нужны.
3. В `docs/cli-command-map.md` разместить текущую карту всех публичных команд: назначение, пример, ссылка на справку/документацию и релевантное интеграционное покрытие либо явное указание его отсутствия. README содержит обзор и ссылку на карту. Архивные command-map остаются историческими свидетельствами; ссылки JTBD согласуются с актуальной картой. Это устраняет разрозненность текущих ссылок без переписывания истории.
4. Материалы скилла обновляются через отдельное issue #6; README приложения ссылается на `https://github.com/mesilov/bitrix24-cli-skill`. Скилл опирается только на публичный CLI и сохраняет существующие ограничения.
5. Корневой `--help`/`-h` без имени команды направляется в обзор приложения. Порядок разделов: назначение b24cli; синтаксис `b24cli [global options] COMMAND [arguments] [options]`; список публичных команд с краткими описаниями, сгруппированный по namespace; глобальные опции; примеры создания, просмотра и поиска задач; вызовы `b24cli COMMAND --help` и `b24cli help COMMAND` и ссылка на документацию. Список формируется из зарегистрированных публичных команд, включая доступные стандартные команды Symfony, чтобы не расходиться с `list`; шаблонный пример `list test` в корневой справке не используется.
6. Существующая маршрутизация help должна различать корневой запрос, `COMMAND --help`/`help COMMAND` и явный `list --help`/`help list`. Обзор приложения не должен подменять командную справку или менять вызов `b24cli` без аргументов, `list`, его namespace и форматы. Примеры используют существующие `task:add`, `task:show` и `task:find`; у add показываются обязательные поля и `--dry-run`, без секретов. Показ справки не выполняет примеры, не разрешает credentials и не делает API-запросов.
7. Изменение корневого вывода зафиксировано delta spec `specs/cli-experience/spec.md`; прежний `skip_specs: true` удаляется. Изменения исполнения прикладных команд по-прежнему вне области этого плана.
8. Корневой `b24cli --about` без имени команды выводит краткую карточку приложения: имя b24cli и назначение; фактическая версия из того же источника `BuildVersion`, который используется `--version`; автор Maksim Mesilov; лицензия `bitrix24-cli-license`, основанная на BSD-3-Clause; ссылки `https://github.com/mesilov/bitrix24-cli` и `https://github.com/mesilov/bitrix24-cli-skill`. Автор и название лицензии согласуются с LICENSE/README; в about не подставляется запланированная 0.2.0 вместо версии запущенной сборки. Содержимое about отображается локально без разрешения подключения, записи конфигурации, API-запросов или автоматического открытия ссылок. `--about` должен быть обнаружим в общей справке; назначение и метаданные согласуются с README, docs и обновлением скилла.

## Risks / Trade-offs

- [dev меняется до релиза] → зафиксировать source SHA исходной сверки и повторить проверку на артефакте 0.2.0 перед закрытием issue.
- [Пример успешно разобран, но права/данные портала отличаются] → различать синтаксическую проверку и live acceptance; не заявлять последнее по справке.
- [Карта скилла расходится с приложением] → взаимные ссылки issues и одинаковая версия/source SHA сверки.

## Migration Plan

Изменения справки и документации доставляются обычным MR в dev. Обратный ход — revert соответствующего documentation/help commit; данные пользователя и подключения не мигрируют. По завершении проверки архивировать change и обновить путь в обоих issues.
