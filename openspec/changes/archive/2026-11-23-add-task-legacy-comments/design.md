# Design

## Context

`task:chat:list` строится на `ChatSupport::scan`: курсорный обход `im.dialog.messages.get` с бюджетом и metadata `scope`, `complete`, `scanned`, `returned`, `hasMore`, `reason`. REST1-адаптеры задач уже есть — например, `Rest1TimeEntryAdapter` для `task.elapseditem.getlist`. Ошибки API приходят из `SdkApiTransport` как `Failure('api-error', ..., ['apiErrorCode' => <код>])`, а `ERROR_METHOD_NOT_FOUND` распознаётся отдельно. Список маршрутов команды для policy и scope объявлен в `CommandCatalog`.

Поведение метода на портале описано в [research.md](research.md). Для дизайна важны четыре факта: `start` игнорируется; `FILTER` без `ORDER` отклоняется; префикс `<ID` работает, хотя не документирован; ссылки на вложения содержат токен.

Change `add-weekly-task-report` ещё не архивирован, но тоже меняет требование `Exact MVP command registration` (на 50 команд). Дельта этого change опирается на его текст и задаёт 51.

## Goals / Non-Goals

**Goals:**
- Отдельная read-команда с собственным курсором и metadata, переиспользующая общий каркас вывода и обработки ошибок.
- Ссылки с токенами не покидают адаптер.

**Non-Goals:**
- Автоматический вызов `task.commentitem.getlist` из `task:chat:list`.
- Определение по API, переведена ли задача на новый чат.

## Decisions

### Отдельная команда `task:legacy:comment:list`, а не флаг `task:chat:list --source`

У старой ленты свои ID, своя версия API, свой курсор и свои ошибки. `task:chat:update/delete` принимают ID сообщений чата, и флаг источника в той же группе команд путал бы ID. Отдельная команда даёт отдельный маршрут для policy (`strict-rest3` отклоняет только её) и не меняет контракт `task:chat:list`.

Альтернатива: `task:chat:list --source legacy|chat|all`. Отклонена: в одном выводе пришлось бы различать два типа ID и две полноты, а `--all` по умолчанию добавил бы REST1-маршрут к команде, которую `strict-rest3` сейчас допускает только с IM-маршрутом.

### Легаси-неймспейс `task:legacy:`

Имя `task:legacy:comment:list` оставляет команду в `b24cli list task`, где ищут всё про задачи, и выделяет устаревшие поверхности старой карточки в отдельную группу. Пометка повторяется в описании списка (`[legacy]`), первой строке help, `meta.legacy` и заголовке человекочитаемого вывода. Цвет не используется: пометка должна читаться в CI и при перенаправлении вывода.

Альтернативы: корневой `legacy:task:comment:list` заметнее, но убирает команду из списка задач; `task:comment:legacy:list` прячет пометку в середине имени.

### Курсор по ID вместо `start`

Портал игнорирует `start` и не возвращает `next`/`total`. Поэтому:

- `--after ID` и `--all` без курсора: `ORDER {ID: asc}`, `FILTER {">ID": cursor}`, начиная с `cursor = 0` или с переданного ID.
- Окно последних комментариев (без курсора и без `--all`) и `--before ID`: `ORDER {ID: desc}`, первая страница без фильтра или с `FILTER {"<ID": before}`, следующие — `"<ID": min(id)`. Результат разворачивается в порядок по возрастанию.
- Обход идёт до пустой страницы: размер страницы не подтверждён, поэтому неполная страница не считается последней. Это стоит одного лишнего запроса в конце.
- `ORDER` передаётся всегда, иначе портал отклоняет `FILTER`.
- Нет ни одного нового ID за курсором → `pagination-no-progress`, обход прекращается.

Префикс `<` не документирован. Если портал его проигнорирует, desc-страница повторит те же ID и сработает проверка `pagination-no-progress`. Ложной полноты не будет, только частичный результат с причиной. `--all` использует только документированный `>`.

Альтернатива: читать всё по возрастанию и брать хвост для окна последних. Отклонена: для `--limit 20` на длинной ленте это читало бы всю ленту в пределах бюджета.

### Ошибки источника

Адаптер не превращает ошибки в пустой список. Сервис различает:

- `apiErrorCode = ERROR_METHOD_NOT_FOUND` → ошибка `legacy-comments-unavailable`, сообщение «прежняя лента комментариев не проверена: метод недоступен на портале»;
- `apiErrorCode = ERROR_CORE` на первой странице → ошибка `legacy-comments-unavailable` с подсказкой проверить TASK_ID и доступ к задаче (так портал отвечает на отсутствующую задачу);
- `permission-denied` и нехватку scope оставляем общим кодам;
- ошибку страницы после хотя бы одной успешной → частичный результат `page-error`, exit 3, как в `ChatSupport::scan`.

### Нормализация вложений

Адаптер сразу маппит `ATTACHED_OBJECTS` в `attachments: [{attachmentId, fileId, name, size}]` (int, int, string, int) и отбрасывает `DOWNLOAD_URL`, `VIEW_URL` и прочие ключи. Сырой ответ дальше адаптера не передаётся, поэтому токен не попадает ни в presenter, ни в debug-журнал результата. Журнал транспорта уже маскирует ключи с `auth`; тест должен подтвердить, что URL с `auth[ap]` не появляется в журнале.

`POST_MESSAGE` выводится как есть, в поле `text`, без преобразования BBCode. `AUTHOR_EMAIL` не выводится: для задачи достаточно `authorId` и `authorName`.

### Признак в `task:chat:list`

`meta.legacyComments = {status: "not-checked", command: "task:legacy:comment:list <TASK_ID>"}` добавляется всегда, без анализа текста служебного сообщения. Определять миграцию по тексту ненадёжно (текст локализован), а по API — не документировано. Человекочитаемый вывод добавляет строку-подсказку, `--plain` пишет её в stderr, как сводку звонков.

## Risks / Trade-offs

- [Метод не развивается и может исчезнуть] → `ERROR_METHOD_NOT_FOUND` даёт явную ошибку «не проверено», а не пустую ленту; в help указано, что маршрут — REST1 и метод устаревший.
- [Размер страницы неизвестен] → обход до пустой страницы, независимо от размера.
- [Префикс `<ID` не документирован] → используется только для окна последних и `--before`; при игнорировании срабатывает `pagination-no-progress`.
- [Конфликт дельт с `add-weekly-task-report`] → архивировать `add-weekly-task-report` раньше этого change; при архивировании сверить число команд с `CommandCatalog`.
- [Права второго пользователя не проверены] → в live-приёмке проверить задачу, где второй пользователь не участник; при недоступности зафиксировать границу.

## Migration Plan

Новая команда и новое поле metadata. Существующие поля и коды выхода не меняются, миграция не требуется. Откат — удаление команды.
