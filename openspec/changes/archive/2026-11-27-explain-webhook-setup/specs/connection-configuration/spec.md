# Spec Delta

## ADDED Requirements

### Requirement: Documented incoming webhook setup
`docs/auth.md` SHALL содержать раздел со стабильным якорем `incoming-webhook`. Раздел объясняет, как создать входящий вебхук Битрикс24 для b24cli: путь в интерфейсе, где выбрать права, какое поле скопировать, что делать без доступа или без REST на тарифе, вид URL, почему он секретен и как перевыпустить вебхук. Утверждения об интерфейсе MUST ссылаться на официальную документацию. README MUST вести к этому разделу с шага входа.

#### Scenario: New user follows the login docs
- **WHEN** пользователь после установки открывает раздел подключения в README или `docs/auth.md`
- **THEN** он видит шаги *Разработчикам → Готовые сценарии → Другое → Входящий вебхук*, выбор прав в *Настройка прав* и поле *Вебхук для вызова rest api*, значение которого нужно вставить в `auth:login`
- **AND** видит ссылку на официальную статью о первом запросе через вебхук и ссылку на документацию проекта о нужных правах вместо собственного списка прав

#### Scenario: Webhook option is unavailable
- **WHEN** в разделе *Разработчикам* нет пункта *Входящий вебхук* либо портал сообщает, что REST API недоступен на тарифе
- **THEN** раздел говорит, что право создавать вебхуки выдаёт администратор, и ведёт к официальной инструкции; для тарифа — к официальной статье о доступе к REST API

#### Scenario: URL shape without real secrets
- **WHEN** раздел показывает пример URL вебхука
- **THEN** пример использует вымышленный домен и явный заполнитель секретного кода, объясняет адрес портала, ID пользователя и секретный код и не содержит реального секрета

#### Scenario: Why input is hidden
- **WHEN** пользователь читает, почему `auth:login` скрывает ввод
- **THEN** раздел объясняет, что код в пути URL даёт доступ к порталу с правами создателя вебхука в пределах выданных прав, поэтому URL нельзя передавать аргументом, публиковать или оставлять в истории shell

#### Scenario: Rotate a leaked or expired webhook
- **WHEN** вебхук скомпрометирован или истёк, и `auth:login` или `auth:status` сообщает об ошибке авторизации
- **THEN** раздел объясняет, где найти вебхук в списке *Интеграции*, как перевыпустить его через *Перегенерировать* и как сохранить новый URL командой `auth:login NAME --replace` без потери настроек профиля

### Requirement: Webhook guidance in auth:login help
Справка `auth:login` SHALL начинаться с краткого объяснения: ожидается URL входящего вебхука Битрикс24, где его создать, почему ввод скрыт; в конце SHALL быть ссылка на раздел `incoming-webhook` руководства. Справка MUST оставаться локальной операцией без credentials, записи конфигурации и запросов к порталу и MUST соответствовать требованиям к русской справке.

#### Scenario: Read login help without a connection
- **WHEN** пользователь без настроенного подключения вызывает `b24cli auth:login --help` или `b24cli help auth:login`
- **THEN** оба вызова возвращают 0 и одинаковый вывод с путём *Разработчикам → Готовые сценарии → Другое → Входящий вебхук*, причиной скрытого ввода и ссылкой на `docs/auth.md#incoming-webhook`
- **AND** не создают конфигурацию, не читают credentials и не обращаются к порталу

### Requirement: Interactive webhook prompt explains expected input
Интерактивный `auth:login` в TTY SHALL перед скрытым вводом выводить в stderr короткую русскую подсказку: что вставить, где это взять, что ввод не отображается, ссылку на руководство. Строка запроса SHALL быть русской. Подсказка MUST NOT появляться при `--webhook-stdin`, при ошибке до ввода и в stdout.

#### Scenario: Interactive prompt
- **WHEN** пользователь выполняет `b24cli auth:login work` в интерактивном терминале для нового профиля
- **THEN** stderr содержит подсказку о URL входящего вебхука, пути в интерфейсе Битрикс24, скрытом вводе и ссылку на руководство, затем строку `URL входящего вебхука: `; введённое значение не отображается
- **AND** stdout не содержит подсказки и строки запроса

#### Scenario: Interactive replacement
- **WHEN** пользователь выполняет `b24cli auth:login work --replace` в интерактивном терминале для существующего профиля
- **THEN** выводятся та же подсказка и строка запроса, остальное поведение `--replace` не меняется

#### Scenario: Piped or noninteractive input
- **WHEN** `auth:login` получает вебхук через `--webhook-stdin` либо завершается usage-error при `-n` без `--webhook-stdin`
- **THEN** подсказка и строка запроса не выводятся, коды завершения остаются прежними

#### Scenario: Errors before input
- **WHEN** `auth:login` вызывается для существующего NAME без `--replace`, для отсутствующего NAME с `--replace` либо с `--api-policy strict-rest3` без `--skip-check`
- **THEN** ошибка возвращается до подсказки и до ввода вебхука
