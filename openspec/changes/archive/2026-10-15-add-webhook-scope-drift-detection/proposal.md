# Proposal

## Why

После обновления CLI старый входящий вебхук может не иметь scope новых возможностей. Пользователь получает ошибки доступа без объяснения, какие разрешения добавить. Решение согласовано 2026-10-15 для 0.3.0.

## What Changes

- Поставлять с CLI манифест требований scope для фактических маршрутов команд.
- Хранить независимые снимки прав подключений в защищённом `state.json` рядом с `config.json`; не менять config schema v1 и credential files.
- Проверять права лениво с TTL 86400 секунд, при смене требований/credentials и явно через `connection:check`.
- Блокировать только команду/режим с подтверждённым отсутствующим scope. Сохранять независимые команды, offline/dry-run, сведения о stale/unknown и backoff.
- Добавить проверяемую диагностику, защиту конкурентных записей и документацию.

## Capabilities

### New Capabilities

- `connection-scope-validation`: манифест требований, кеш прав подключения, периодическая/явная проверка и точечная блокировка.

### Modified Capabilities

Нет. Существующие правила выбора подключения и локальных connection-команд сохраняются; новая remote-диагностика имеет отдельный контракт.

## Impact

Затрагиваются CommandRunner, ConnectionManager, регистрация команд, SDK transport, файловое состояние и CLI reference. Новый вызов: REST1 `scope` без `full`. Новые зависимости не нужны. Не входят OAuth, автоматическое изменение webhook, фоновые задания, повтор мутаций, доказательство объектных прав и выпуск релиза.
