# Proposal

## Why

Несколько задач должны независимо запускаться на одном хосте в разных Git worktree. Текущее Docker-окружение использует общий тег образа и не задаёт устойчивую идентичность окружения, поэтому независимость сборки, запуска и остановки разных checkout не гарантирована.

## What Changes

- Ввести устойчивое уникальное имя Compose-проекта для каждого checkout, в том числе worktree с одинаковым именем каталога в разных путях.
- Изолировать изменяемые Docker-ресурсы и теги собираемых образов, исходники, зависимости и локальную конфигурацию каждого worktree.
- Обеспечить запуск существующих Make-команд из выбранного checkout и остановку только его окружения.
- Документировать подготовку нового worktree без неявного копирования секретов; игнорировать локальный каталог worktree и генерируемые служебные файлы.
- Добавить воспроизводимую проверку двух одновременно работающих worktree и безопасного освобождения ресурсов.

## Capabilities

### New Capabilities

- `worktree-development`: независимая подготовка, сборка, запуск, проверка и остановка окружений разработки нескольких checkout на одном Docker-хосте.

### Modified Capabilities

Нет: актуальные спецификации пока отсутствуют.

## Impact

`Makefile`, `docker-compose.yaml`, `.gitignore`, `README.md`, проверки окружения разработки. Прикладные команды Bitrix24 и публичный CLI-контракт не меняются. Новые сервисы, порты, БД и менеджер жизненного цикла Git worktree в область изменения не входят.
