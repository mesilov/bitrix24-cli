# Proposal

## Why

22 согласованных JTBD и их IDs находятся в OpenSpec; пользователям нужен доступный список в docs с группировкой по рабочим ролям и трассировкой на текущие команды и интеграционные тесты.

## What Changes

- Добавить `docs/task-jtbd.md`: руководитель отдела (PM-01…07), аккаунт-менеджер проекта (AM-01…07), рядовой исполнитель (EMP-01…08).
- Сохранить исходные ID, ситуацию, работу, цель и признак успеха из task-workflows.
- В каждом сценарии объединить текущие и планируемые команды в одну таблицу «Статус / Команда / Тест»; статусы с эмоджи отражают наличие реализации или план, не результат запуска теста.
- Показать текущие и планируемые команды по jtbd-coverage и CommandCatalog, ссылки на файлы командных integration tests и пробелы сквозной приёмки.
- Добавить блок «Роли» с описаниями каждой роли на основе существующих JTBD и ссылками на соответствующие разделы.
- Раздел «Как читать трассировку» разместить в конце документа.
- Перед merge сверить новые канонические IDs PM-07/AM-07/EMP-08 и runtime результатов с текущей dev; сохранить прежние 19 IDs.
- Добавить README navigation и CHANGELOG Unreleased со ссылкой #80.

## Capabilities

### New Capabilities

Нет: изменение только документации (`skip_specs: true`).

### Modified Capabilities

Нет: task-workflows и исходная матрица остаются источниками требований.

## Impact

`docs/task-jtbd.md`, README.md, CHANGELOG.md, артефакты этого change. Runtime, CLI flags, API contracts и тесты не меняются. Новые live-проверки и закрытие #42 вне области; наличие ссылок на тесты не доказывает их прохождение или полноту JTBD.
