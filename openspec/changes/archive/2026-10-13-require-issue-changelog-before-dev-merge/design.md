# Design

## Context

См. `proposal.md`. В репозитории есть `CHANGELOG.md` с разделом `Unreleased`; скилл не включает changelog в проверку готовности MR.

## Goals / Non-Goals

**Goals:** проверять собственную содержательную запись MR на текущем SHA для любой работы по issue.

**Non-Goals:** автоматический CI gate, изменения runtime CLI и ретроспективное переписывание changelog завершённых задач.

## Decisions

- Включить правило в отдельный раздел скилла и в проверку перед MR. Указать повторную проверку непосредственно перед merge, после обновления ветки или разрешения конфликтов.
- Проверять `git diff <remote>/dev...HEAD -- CHANGELOG.md`, затем содержимое diff: запись в `Unreleased`, соответствие итоговому объёму MR и ссылка на issue. Присутствие файла или старой записи в базовой ветке не доказывает правку текущего MR.
- Не вводить исключений по категории работы: последующие MR документации, tooling и архивирования по той же issue тоже содержат запись о собственном результате. Проверка остаётся обязанностью мейнтейнера, а не новой автоматической проверкой CI.

## Risks / Trade-offs

- Формальное изменение файла без описания результата → требовать содержательную проверку записи, а не только имя файла в diff.
- Изменение diff после синхронизации ветки → повторять проверку на актуальном SHA перед merge.
