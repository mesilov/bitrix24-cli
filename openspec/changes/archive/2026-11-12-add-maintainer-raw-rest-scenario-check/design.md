# Design

## Context

См. proposal.md. База `dev`: `201e643c35e7f3733fc5afed3a0d82e53ccdb811`. Основной checkout содержит устаревшую редакцию скилла на `main` и незакоммиченный раздел «Только gh» в `AGENTS.md` и скилле. Актуальная `dev` дополнительно содержит JTBD, обязательный MCP, CHANGELOG, builds/RC, синхронизацию перед MR и проверку замечаний.

## Goals / Non-Goals

Цель — проверять фактическое поведение портала по сценариям issue до фиксации требований. Правка не добавляет команду `api:call` в CLI, не меняет integration-тесты и не заменяет приёмку на портале.

## Decisions

1. **Отдельный подраздел и ссылки из workflow.** Правила шага описаны один раз в подразделе «Проверка сценариев issue сырыми запросами к REST API». Пункты workflow, чек-лист перед MR и verify ссылаются на него. Это исключает дублирование.
2. **Релевантность решает мейнтейнер, решение фиксируется.** Шаг обязателен, если issue добавляет или меняет REST-вызовы, зависит от поведения портала или описывает баг на портале. Для документации, CI и локальной логики без API он не нужен. Решение и причина записываются в `design.md` change, чтобы пропуск был явным.
3. **Момент выполнения.** После сверки методов через MCP и до фиксации design/spec/tasks: результат влияет на требования. На verify повторяются только сценарии, затронутые изменениями после первой проверки.
4. **Прямой запрос без CLI и SDK.** Это отделяет поведение портала от кода проекта. URL и формат запроса берутся из документации используемой версии REST API.
5. **Безопасность.** Webhook читается из env-файла и передаётся в `curl` через `--config -`, а не в argv. Webhook не попадает в вывод, change и issue. По умолчанию разрешены только чтение и metadata. Запись разрешена только в тестовой группе `B24CLI_TEST_GROUP_ID` с удалением созданных объектов. Права проверяются через `B24CLI_TEST_RESTRICTED_WEBHOOK`, если он задан.
6. **Фиксация.** Раздел `## Проверка на портале` в `design.md`: дата, портал без секретов, метод, версия REST, payload, сокращённый ответ и вывод по каждому сценарию. Расхождение с документацией или issue исправляется в issue и spec до реализации.
7. **Правило `gh`.** Переносится без изменения смысла из основного checkout в `AGENTS.md` и раздел «Управление разработкой в GitHub» скилла.

## Risks / Trade-offs

- Утечка webhook через argv, историю shell или вывод → `curl --config -`, запрет печати ответа с URL и маскирование.
- Изменение рабочих данных портала → только чтение по умолчанию, запись только в тестовой группе с cleanup.
- Сырые запросы ошибочно считаются приёмкой → явная граница: они не заменяют `make integration` и portal acceptance.
- Устаревшая локальная копия может затереть разделы `dev` → правка в отдельном worktree от `dev`, сравнение diff.
