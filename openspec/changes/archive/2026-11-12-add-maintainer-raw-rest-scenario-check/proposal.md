# Proposal

## Why

Сейчас имена, типы и обязательность полей Bitrix24 сверяются с документацией через MCP. Фактическое поведение портала (фильтры, права, статусы, формат ответа, ошибки) впервые проверяется в integration-тестах или при приёмке, то есть после реализации. Расхождения портала с документацией и с ожиданиями issue находятся поздно и требуют переделки design, spec и кода.

Кроме того, правило «только `gh` в неинтерактивном режиме» для операций с GitHub согласовано и применяется локально, но отсутствует в `dev`.

## What Changes

- Добавить в скилл мейнтейнера отдельный шаг: проверка сценариев issue сырыми запросами к REST API Битрикс24 напрямую по webhook, без `b24cli` и SDK, если это релевантно для issue.
- Определить условия релевантности, момент выполнения (после сверки через MCP, до фиксации design/spec/tasks), безопасность webhook, ограничения записи и формат фиксации результата в change.
- Встроить шаг в «Порядок работы над feature или bugfix», в проверки перед MR и в verify; при расхождении с документацией или issue сначала обновлять issue и spec.
- Перенести правило «только `gh`» в `AGENTS.md` и скилл `dev`.
- Сохранить все актуальные разделы `dev`.

## Capabilities

### New Capabilities

Нет. Изменяются инструкции сопровождения, а не поведение CLI.

### Modified Capabilities

Нет. Новый автоматический CI gate не добавляется. Для документационной правки задано `skip_specs: true`.

## Impact

Изменяются `.agents/skills/bitrix24-cli-maintainer/SKILL.md`, `AGENTS.md`, `CHANGELOG.md` и артефакты этого change. Runtime CLI, API-вызовы и JTBD не меняются. Незакоммиченные изменения основного checkout сохраняются.
