# Design

## Context

См. `proposal.md`. README ведёт к CI artifacts, а `build/README.md` сейчас содержит неполный macOS/PATH пример. `build/release-assets.py` помещает executable, metadata, `THIRD-PARTY-NOTICES.md`, `YIIPRESS-LICENSE.txt` и `runtime-licenses/` непосредственно в корень platform archive.

## Goals / Non-Goals

**Goals:** копируемые команды для macOS/zsh без sudo, с проверкой целостности перед распаковкой, локальным запуском и пользовательской установкой.

**Non-Goals:** изменение PHP runtime, installer, глобального PATH, signing/notarization или обход macOS Gatekeeper. #23 остаётся отдельной задачей.

## Decisions

- README содержит короткий первый запуск и прямую ссылку на полную установку. Дублировать длинную инструкцию не нужно: checksum и установка поддерживаются в `build/README.md`.
- `./b24cli` использует явный относительный путь; `b24cli` ищется в PATH. Добавлять `.` в PATH не предлагается, поскольку это делает случайные файлы текущего каталога командами.
- macOS пример проверяет только archive нужной платформы из того же Release/CI run. `&&` не позволяет распаковать archive при неуспешном checksum. CI artifact ZIP является внешним контейнером; platform archive проверяется после извлечения этого контейнера.
- `install -m 755` копирует binary в `$HOME/.local/bin`; внешние notices сохраняются в `$HOME/.local/share/b24cli/`. Установка в системный bin или symlink к Downloads не требуется.
- PATH текущей сессии настраивается через `export`. Постоянная строка добавляется в `${ZDOTDIR:-$HOME}/.zshrc` с проверкой наличия точной строки, чтобы повторная установка не дублировала настройку. Путь пользователя берётся при чтении `.zshrc`, не фиксируется для другого пользователя.
- После перехода в другой каталог проверяются `command -v b24cli`, версия и новая interactive login zsh (`zsh -lic`). Для документации нужна проверка команд на настоящем CI archive в изолированном пользовательском каталоге; новый тестовый framework не добавляется.

## Risks / Trade-offs

- [macOS может блокировать downloaded executable] → ссылка на #23; PATH не представляется решением этой блокировки.
- [Пользователь копирует команды после checksum failure] → явное условие успеха, распаковка через `&&`; установка выполняется только после успешного локального запуска.
- [Настройка чужого профиля при проверке] → временный каталог и отдельный ZDOTDIR; реальные dotfiles пользователя не редактируются.
- [Другой b24cli раньше в PATH] → пользовательский bin добавляется первым, `rehash` и `command -v` подтверждают найденный путь.
