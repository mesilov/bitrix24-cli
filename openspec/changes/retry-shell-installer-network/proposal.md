# Proposal

## Why

При временном HTTP 504 определение latest немедленно прерывает установку. Независимые строки README затем пытаются подключить отсутствующий env и запустить неустановленный b24cli, скрывая первичную причину дополнительными ошибками.

## What Changes

- Добавить ограниченные повторы curl при временных HTTP-ошибках, таймаутах и отказе соединения для определения latest и загрузки архива/SHA256SUMS.
- Сохранить проверку HTTPS, целостности и версии, а также прежнюю установку при окончательном сбое.
- Связать загрузку скрипта, установку, активацию env и проверку версии в README и руководстве установки: следующий шаг выполняется только после успеха предыдущего, включая ошибку левой части pipeline.
- Проверить поведение настоящего curl на локальном HTTP стенде и выполнить блоки документации в Bash/zsh.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `binary-distribution`: устойчивость shell installer к временным ошибкам и условное выполнение команд пользовательской установки.

## Impact

`install.sh`, `README.md`, `docs/install.md`, `build/tests/shell-installer-check.py`, workflow shell installer и `CHANGELOG.md`. Используются штатные retry-возможности curl; новые зависимости пользователю не нужны. Bitrix24 REST API, PHP-команды и формат release assets не меняются.
