# Proposal

## Why

До выпуска 0.2.0 нужно проверить финальный scope и артефакты, поскольку каталог команд и документация могут измениться после реализации #100. Приёмка исходников не заменяет проверку релизных пакетов.

## What Changes

- Собрать релизные пакеты по зафиксированному source SHA и согласованному scope milestone.
- Повторить все проверки help/about, примеров, README/docs/JTBD и карты публичного CLI из #100 на финальных исходниках и артефактах; при расхождениях актуализировать работы.
- Передать финальный каталог и version/source SHA в issue скилла #6.
- Подготовить release notes, CHANGELOG, архивы и SHA256SUMS; сохранить результаты Linux/macOS/Windows и terminal CI.
- По явному запросу пользователя подготовить и принять `0.2.0-rc-1` через builds без GitHub Release. Зафиксировать merge PR #132, точный RC SHA и проверку уже собранных архивов на трёх native runners; результаты RC не отмечают автоматически приёмку финальной stable 0.2.0.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Нет: это релизная процедура для существующих требований `binary-distribution` и `cli-experience`, без нового runtime-контракта (`skip_specs: true`). Найденные новые изменения поведения оформляются связанным change.

## Impact

Сборка, упаковка, релизная документация, приёмка и координация скилла. Постановка этого change не означает запуск сборки, promotion в main, создание тега или публикацию Release.
